# WordPeek

<p><img src="icon-preview.png" width="88" height="88" alt="Иконка WordPeek" align="left" hspace="12"></p>

Живой перевод текста из активного поля ввода в любом приложении Windows (EN↔RU).
Пока вы печатаете, под кареткой появляется строка с переводом. Клик по ней — копирование.

## Запуск

`bin\out\WordPeek.exe` — двойной клик. Приложение живёт в трее, окна не открывает.

- Иконка «A» в трее → меню: включить/выключить, настройки, выход.
- Горячая клавиша по умолчанию: **Ctrl + Alt + T** (вкл/выкл).
- Клик по плашке перевода копирует её в буфер и прячет.

## Настройки

Меню в трее → «Настройки…»:

- горячая клавиша (кнопка → нажать новую комбинацию);
- сервис перевода: Google без ключа (по умолчанию) или DeepL с ключом API;
- задержка отправки, мс (по умолчанию 130).

Настройки сохраняются в `settings.json` рядом с exe.

## Как это работает

1. Наблюдатель опрашивает активное поле через UI Automation (`TextPattern` / `ValuePattern`).
2. Читает текст и прямоугольник каретки; у свёрнутой каретки диапазон растягивается на символ.
3. После паузы 130 мс текст уходит в сервис перевода (один запрос в полёте, кэш ответов).
4. Плашка рисуется всегда поверх (topmost), но не забирает фокус.

## Диагностика

Рядом с exe пишется `wordpeek.log` — что за поле найдено и какие ошибки были.

Режимы запуска из командной строки:

```
WordPeek.exe --probe 30      # 30 секунд писать в probe.log всё, что видит UIA
WordPeek.exe --selftest      # проверить чтение текста/каретки на своём поле → selftest.log
WordPeek.exe --translate     # прогнать сервис перевода → translate.log
WordPeek.exe --demo          # нарисовать плашку и сохранить overlay.png
WordPeek.exe --hooktest      # проверить перехват клавиатуры → hooktest.log
WordPeek.exe --tree 4 chrome # выгрузить дерево доступности окна → tree.log
WordPeek.exe --parsetest     # проверить разбор ответов Google → parsetest.log
WordPeek.exe --icontest      # проверить иконку трея → trayicon.png / .ico
WordPeek.exe --fieldtest     # разобрать поле активного окна → fieldtest.log
```

## Chromium-приложения (Chrome, Telegram, Electron)

Такие приложения не строят дерево доступности, пока система не сообщит, что работает
экранный диктор. WordPeek делает это при старте (`SPI_SETSCREENREADER`) и возвращает
настройку при выходе. Проверить, сработало ли, можно по строке в логе:

```
accessibility: request=True
```

Если доступность не включилась, работает **запасной пассивный перехват клавиатуры**:
нажатия запоминаются и текст переводится. Плашка в этом случае встаёт у курсора мыши,
потому что координаты каретки из такого приложения недоступны.

Дополнительно Chrome умеет включать доступность вручную: открой `chrome://accessibility`,
поставь галочку «Native accessibility API support» для нужной вкладки — тогда текст поля
пойдёт через UI Automation с точной позицией каретки.

Важно: перехват видит всё, что печатается, включая пароли. Отключается галочкой
«Перехват клавиатуры» в настройках.

## Известные ограничения

- Поля паролей в обычных приложениях игнорируются намеренно (UIA их помечает).
- Приложения, запущенные от администратора, недоступны, если WordPeek запущен без админа.
- Терминал, консоль и Java-приложения текст через UIA не отдают.
- Для Chromium-приложений координаты каретки недоступны — плашка встаёт у курсора мыши.

## Что означают строки в wordpeek.log

| Строка | Значение |
|---|---|
| `started`, `build ...` | запуск и время сборки |
| `tray: создан` | иконка в трее зарегистрирована |
| `accessibility: request=... error=...` | попытка включить доступность для Chromium-приложений |
| `keyboard hook: установлен` | пассивный перехват клавиатуры включён |
| `hook call #1` | хук реально получает нажатия |
| `включаю опрос клавиш` | хук не сработал, включён обходной опрос |
| `snap: field=... proc=...` | смена активного поля или приложения |
| `field proc=Notepad ... text="..."` | найден текст поля |
| `hook: "..."` | текст восстановлен перехватом клавиатуры |
| `ok: "..."` | получен перевод |
| `replace focus: попытка N` | кому достался клавиатурный фокус перед заменой |
| `replace check: успешно` | текст в поле действительно заменился |
| `replace check: НЕ СРАБОТАЛО` | замена не применилась |
| `blind: proc=chrome` | приложение не отдаёт текст через UIA |

Если `SPI_SETSCREENREADER` запрещён системой (в логе `error=5`), доступность Chrome
не включится. Тогда работает перехват клавиатуры либо ручное включение через
`chrome://accessibility` → «Native accessibility API support» для нужной вкладки.

## Сборка из исходников

Нужен Windows 10/11 x64 и .NET SDK 8.0 (проект — WPF + WinForms, `net8.0-windows`).

```powershell
git clone https://github.com/slavauspensky-nv/WordPeek.git
cd WordPeek
dotnet build -c Release
```

Готовый файл — `bin\Release\net8.0-windows\WordPeek.exe`; рядом должны лежать
`WordPeek.dll`, `WordPeek.runtimeconfig.json`, `WordPeek.deps.json`, папки `fonts\` и `sounds\`.
Для запуска нужен .NET Desktop Runtime 8.

## Шрифты

В `fonts/` лежат 25 шрифтов с Google Fonts, которые использует плашка перевода и окно
обучения: Alegreya, Caveat, Comfortaa, Fira Code, Fira Sans, JetBrains Mono, Lato, Lora,
Marck Script, Montserrat, Noto Sans, Nunito, Open Sans, Oswald, Philosopher, Playfair Display,
Press Start 2P, PT Sans, PT Serif, Roboto, Rubik, Russo One, Source Sans 3, Ubuntu, Yeseva One.

Большинство распространяются по SIL Open Font License 1.1 (OFL) — их можно свободно
использовать и встраивать в приложение, если сохранять условия лицензии и не продавать
шрифты отдельно. Перед публичным релизом стоит свериться с лицензией каждого файла
на странице шрифта в Google Fonts.
